# TG TOP — edge anti-DDoS policy

## Production status

Edge policy активна на `tgtop.me` в Nginx. Она защищает публичный reverse proxy до Express, поэтому перегруженные запросы не занимают tRPC, базу данных или payout worker. Проверка после применения подтвердила: Nginx, сайт, оба Telegram-бота и payout worker active; локальный и публичный `/healthz` отвечают `200`.

| Контур | Правило | Причина |
|---|---:|---|
| Все маршруты | 40 одновременных соединений на IP | Ограничивает медленные и connection-flood атаки, не вводя request throttle для статических файлов. |
| Обычный `/api/trpc/` | 30 запросов/сек на IP, burst 60 | Существенно выше наблюдаемого пика 5 tRPC запросов/сек в sampled access log. |
| `wallet.createTonWithdrawal` | 6 запросов/мин на IP, burst 2 | Добавляет внешний барьер перед уже существующей DB risk policy и idempotency. |
| Reconcile / manual review выплаты | 6 запросов/мин на IP, burst 4 | Не позволяет публичному потоку создавать тяжёлые проверки сети. |
| `/healthz` | 10 запросов/сек на IP, burst 20 | Сохраняет работу мониторинга, не превращая health endpoint в дешёвую DDoS-цель. |
| tRPC request body | 12 MB; финансовые операции 128 KB | Обычные Mini App запросы остаются совместимыми, а чувствительные JSON mutation не принимают тяжёлые payload. |

> `429 Too Many Requests` — нормальный защитный ответ, а не ошибка приложения. Для API и financial routes Nginx добавляет `Retry-After`; access log можно агрегировать по статусу `429` без вывода IP-адресов или пользовательских данных.

## Операционная проверка

После изменения Nginx выполнять только через `scripts/apply-edge-antiddos-vps.sh`. Скрипт сохраняет копию server block и snippets, проверяет `nginx -t`, перезагружает Nginx и проверяет локальный и публичный `/healthz`. При любой ошибке он восстанавливает предыдущую конфигурацию.

Для краткой проверки 429 использовать **только неавторизованный** запрос к финансовому route. Такой probe не создаёт заявку, не резервирует баланс и не запускает worker. Не посылать нагрузочные тесты с реальными Telegram session headers или в момент работы владельца с кошельком.

## Оставшийся риск

Nginx limits защищают HTTP Layer 7 на текущем VPS. Они не заменяют внешний CDN/WAF и не могут самостоятельно поглотить насыщение канала, L3/L4 flood или распределённую сеть IP. Следующий уровень — CDN/WAF перед доменом, мониторинг 429/5xx и alerting. До этого worker, DB jobs и web API уже имеют отдельные application-level ограничения и fail-closed финансовый путь.
